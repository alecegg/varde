Show the page component vocabulary

Usage: varde learn docs blocks [TYPE]

Arguments:
  [TYPE]  Component to describe; omit to describe all

Options:
  -h, --help  Print help

A component is one statement in a ```ui fence: `<id> = <component>(<name>: <value>, ...)`.
The id matches ^[a-z][a-z0-9-]{0,47}$ and is unique in the document. `covers` is reserved:
an optional list of block ids that a block relates to.

chart - A bar, line, area, scatter, donut, sparkline or combo chart from numbers

Fields:
  kind    bar, line, area, scatter, donut, sparkline or combo
  labels  list of x labels (donut: slice names; scatter: omit)
  title, unit, desc  optional text; desc is a one-sentence summary
  right_unit  optional unit of the right axis (combo)
  decimals  optional digits after the point, 0 to 6
  stack, horizontal  optional true or false (bar; stack also combo)
  notes: optional list, up to 12, of markers and bands; x, from and to are
    labels (scatter: numbers); a band's from is not after its to
    x      marker position;  label  required text;  tone  info (default),
           decision, risk, warning or success
    from, to  band ends instead of x (scatter: from below to, inside the data)
  series: list of {name, values}, one per series (up to 12)
    name    series name
    values  list of numbers, one per label
    x       scatter only: list of numbers, one per value
    axis, type  combo only: axis left or right; type bar or line

Line syntax (in a ```ui fence):
  chart = chart(
    kind: "bar",
    title: "Latency",
    unit: "ms",
    desc: "p95 latency fell by about half after the cache change.",
    labels: ["before", "after"],
    series: [
      {"name": "p50", "values": [120, 80]},
      {"name": "p95", "values": [400, 210]},
    ],
    notes: [
      {"x": "after", "label": "cache"},
      {"from": "before", "to": "after", "label": "rollout", "tone": "warning"},
    ],
  )

choice - A question answered by picking one option, or several

Fields:
  question  required text
  options   required list: a string, or a table (label, detail, value)
            recommended: true on one table shows a Recommended badge
  multiple  optional true to allow several picks; default one
  comment   optional true to add a free-text box

Line syntax (in a ```ui fence):
  choice = choice(
    question: "Which database?",
    comment: true,
    options: [
      {"label": "SQLite", "detail": "No server, one file", "recommended": true},
      {"label": "Postgres", "detail": "Shared server", "value": "postgres"},
    ],
  )

comment - A free-text box whose text is stored as the page's answer

Fields:
  label   required text shown above the box
  submit  optional button label; default Send

Line syntax (in a ```ui fence):
  comment = comment(
    label: "Anything we missed?",
    submit: "Send",
  )

data-model - Entities with a key and relations to other entities

Fields:
  entity: list of {name, key, fields, relations}, one per entity
    name       entity name (unique)
    key        field that identifies a row; must be in fields
    fields     {field name: type text, or {type, change, was}}
    relations  optional list of {to, kind}
      to    name of another entity in this block
      kind  one-to-one, one-to-many, many-to-one, many-to-many
  layout  optional: list (default) or graph; graph draws the relations as
          lines between entity boxes, up to 30 entities
  Change (optional on an entity, field, endpoint, parameter or response):
    change  optional: added, modified, removed or renamed
    was     optional previous name, type or value; required for renamed only

Line syntax (in a ```ui fence):
  data-model = data-model(
    entity: [
      {"name": "customer", "key": "id", "fields": {"id": "uuid", "email": "text"}},
      {
        "name": "order",
        "key": "id",
        "fields": {"id": "uuid", "customer_id": "uuid", "total": "cents"},
        "relations": [{"to": "customer", "kind": "many-to-one"}]
      },
    ],
  )

Line syntax (in a ```ui fence):

diagram - A graph or tree of nodes and edges, laid out and drawn as SVG

Fields:
  kind        graph or tree
  nodes: list of {id, label, group, shape, detail}
    id      unique node name
    label   text on the node
    group   optional group id; the group can be collapsed
    shape   optional: box (default), rounded, cylinder or diamond
    detail  optional longer text shown when the node is selected
  edges: optional list of {from, to, label, style}
    from, to  node ids
    label     optional text on the edge
    style     optional: solid (default), dashed or dotted
  groups: optional list of {id, label}, at most 3
  direction   optional LR (graph default) or TB (tree default)
  title, desc optional text
  limits: 200 nodes, 400 edges; a tree has one parent per node

Line syntax (in a ```ui fence):
  diagram = diagram(
    kind: "graph",
    title: "Request path",
    direction: "LR",
    groups: [{"id": "edge", "label": "Edge"}, {"id": "core", "label": "Core"}],
    nodes: [
      {"id": "user", "label": "User", "shape": "rounded"},
      {"id": "gw", "label": "Gateway", "group": "edge", "detail": "Terminates TLS"},
      {"id": "api", "label": "API", "group": "core"},
      {"id": "db", "label": "Database", "group": "core", "shape": "cylinder"},
    ],
    edges: [
      {"from": "user", "to": "gw", "label": "https"},
      {"from": "gw", "to": "api"},
      {"from": "api", "to": "db", "label": "sql", "style": "dashed"},
    ],
  )

endpoint - One HTTP endpoint with its auth rule and responses

Fields:
  method      GET, POST, PUT, PATCH, DELETE, HEAD or OPTIONS
  path        starts with /
  auth        required; "none" must be written to mean public
  summary     optional one line
  request     optional {parameter: type text, or {type, change, was}}
  responses   list of {status, body, change, was}; status 100-599
  Change (optional on an entity, field, endpoint, parameter or response):
    change  optional: added, modified, removed or renamed
    was     optional previous name, type or value; required for renamed only

Line syntax (in a ```ui fence):
  endpoint = endpoint(
    method: "POST",
    path: "/orders",
    auth: "bearer",
    summary: "Create an order",
    request: {"customer_id": "uuid", "total": "cents"},
    responses: [
      {"status": 201, "body": "the new order"},
      {"status": 422, "body": "validation errors"},
    ],
  )

table - A data table: sticky header, sort, filter, typed columns, row groups

Fields:
  caption        optional text
  columns        list of unique column names
  rows           list of rows; each row has one cell per column
  types          optional table: column name to text, number, status, bar, link
                  number and bar cells are numbers; a link cell is a URL
                  or a [label, url] pair
  footnote       optional text under the table
  sticky_column  optional boolean: keep the first column in view
  stack          optional boolean: on phones show each row as labelled pairs
  groups         optional list of {label, rows}: row groups with a header

Line syntax (in a ```ui fence):

ui-states - What a screen shows when empty, loading and failing

Fields:
  screen          optional screen name
  layout          optional: tabs (one state at a time, default) or grid
  [empty]         required; shows = text, or na = reason it cannot occur
  [loading]       required; same form
  [error]         required; same form
  [<other>]       optional extra state in the same form

Line syntax (in a ```ui fence):
  ui-states = ui-states(
    screen: "Orders list",
    empty: {"shows": "No orders yet, with a Create order button"},
    loading: {"shows": "Skeleton rows"},
    error: {"shows": "Message and a Retry button"},

wireframe - Screen regions laid out on a text grid

Fields:
  title    optional text
  grid     equal-width strings; a letter is a region, space or . is empty
  regions  one-letter key = region label; every letter in grid must be declared
  surface  optional device frame: browser, phone or tablet
  kinds    optional one-letter key = nav, text, media, input, action or list;
           each kind has its own hatch pattern and a [kind] label
  notes    optional list of {region, text}; numbered pins and a notes list
  compare  optional second frame {grid, regions, kinds, notes}; the main frame
           is Before and compare is After (side by side on wide screens)

Line syntax (in a ```ui fence):
  wireframe = wireframe(
    title: "Orders list",
    surface: "browser",
    grid: ["HHHHHH", "SSLLLL", "SSLLLL", "FFFFFF"],
    regions: {"H": "header", "S": "filters", "L": "order list", "F": "footer"},
    kinds: {"H": "nav", "S": "input", "L": "list"},
    notes: [{"region": "S", "text": "Filters stay in the URL"}],
  )

Line syntax (in a ```ui fence):

code - A source listing with line numbers, optional marked lines and a Copy button

Fields:
  language  python, js, ts, json or shell are highlighted; others show plain
  source    the code, as one string
  title     optional file name or caption
  lines     optional [from, to]: show only those lines, numbered from `from`
  wrap      optional true: wrap long lines instead of scrolling sideways
  numbers   optional false: hide the line-number gutter
  mark      optional list of line numbers or [from, to] ranges to call out

Line syntax (in a ```ui fence):
  code = code(
    language: "python",
    title: "queue.py",
    source: "def push(item):\n    queue.append(item)\n",
    mark: [2],
  )

annotated-code - A source file with notes on line ranges; quiet stretches fold away

Fields:
  filename  file name shown in the header
  language  python, js, ts, json or shell are highlighted; others show plain
  source    the code, as one string
  notes     list of {lines, note, label, kind}, up to 40; lines is n or 'a-b'
            inside the source; kind is info (default), warn or change
  collapse  optional false: show every line (default folds stretches of 4 or
            more lines that are more than 3 lines from any note)

Line syntax (in a ```ui fence):
  annotated-code = annotated-code(
    filename: "queue.py",
    language: "python",
    source: "def push(item):\n    queue.append(item)\n",
    notes: [
      {"lines": 2, "label": "Unbounded", "note": "`queue` has no limit.", "kind": "warn"},
    ],
  )

file-tree - Changed files as a folder tree with change markers, notes and link to code

Fields:
  title     optional heading
  entries   list of tables, one per file; a path appears once
    path    `dir/file.ext`, no leading slash
    note    optional short text shown on the same row
    role    optional label such as test or config
    change  optional: added, modified, removed or renamed
    was     optional previous name, type or value; required for renamed only
            a renamed file sits at its new path; `was` is the old path
  collapse  optional: close folders deeper than this many levels (default none)
  A file whose path ends with the title of a `code` block links to that block.

Line syntax (in a ```ui fence):
  file-tree = file-tree(
    title: "Changed files",
    collapse: 2,
    entries: [
      {"path": "src/queue.py", "change": "modified", "note": "push returns the id"},
      {"path": "src/retry.py", "change": "added"},
      {"path": "src/backoff.py", "change": "renamed", "was": "src/wait.py"},
      {"path": "tests/test_queue.py", "change": "modified", "role": "test"},
    ],
  )

diff - A before and after text diff, unified or split, with notes on changed lines

Fields:
  filename  optional file name shown in the header
  before    the old text, as one string (may be empty: an added file)
  after     the new text, as one string (may be empty: a removed file)
  patch     instead of before and after: a unified diff string
  mode      optional: unified (default) or split (two columns when wide)
  language  optional: python, js, ts, json or shell are highlighted
  notes     optional list of {side, lines, note}, up to 40; side is before
            or after; lines is n or 'from-to' on that side
    Unchanged runs over 6 lines fold to 3 at each edge; noted lines stay.
    At most 5000 lines are drawn; the rest shows as one 'N more lines' row.

Line syntax (in a ```ui fence):
  diff = diff(
    filename: "queue.py",
    language: "python",
    before: "def push(item):\n    queue.append(item)\n",
    after: "def push(item):\n    if not item:\n        return\n    queue.append(item)\n",
    mode: "unified",
    notes: [{"side": "after", "lines": "2-3", "note": "Skip empty items."}],
  )

checklist - A static checklist with a state word per item and a progress count

Fields:
  title  optional heading

         status is done, open (default) or blocked; checked: true means done
         and must agree with status
    Shows the count as 'N of M done' beside a progress bar. Not interactive.

Line syntax (in a ```ui fence):
  checklist = checklist(
    title: "Acceptance",
    items: [
      {"label": "Queue keeps order", "status": "done"},
      {"label": "Retry uses `backoff`", "note": "API spec", "status": "blocked"},

tabs - Tabs that show other blocks of the page, one panel at a time

Fields:
  tab  list of {label, blocks}, 1 to 12; label is the tab text, blocks the ids
       of other statements to show in that panel (up to 200 ids in all)
    A held block is shown once, in its panel, with its own menu. A block is
    held by one container only, and containers do not nest. Input blocks
    (choice, form, comment, ranking, slider, decision) cannot be held in tabs.
    Without script and in print every panel shows, stacked under its label.

Line syntax (in a ```ui fence):
  tabs = tabs(
    tab: [
      {"label": "Code", "blocks": ["code"]},
      {"label": "Checks", "blocks": ["checklist"]},
    ],
  )

columns - Side-by-side columns that show other blocks of the page

Fields:
  col  list of {label, blocks}, 1 to 4; label is optional text above a column,
       blocks the ids of other statements to show there
    Columns stack below 44rem. A held block is shown once, with its own menu;
    a block is held by one container only and containers do not nest.

Line syntax (in a ```ui fence):
  columns = columns(
    col: [
      {"label": "Before", "blocks": ["callout"]},

matrix - A decision matrix: options as columns, criteria as rows, ratings in cells

Fields:
  title        optional heading
  options      list of {id, label, note}, 1 to 12; label is the column name
  criteria     list of {id, label, weight}, up to 200; weight is 1 to 5
  cells        list of rows, one per criterion; a row has one cell per option
               a cell is yes, partial or no, or high, medium or low (one
               scale per matrix), or plain text; empty reads 'Not rated'
  recommended  optional option id: its column gets a Recommended badge
    Any weight adds a 'Weighted total' row (unweighted criteria count 1; yes
    or high scores 2, partial or medium 1, no or low 0; text scores 0).
    Rows stack on phones; sort and filter come from the table block.

Line syntax (in a ```ui fence):
  matrix = matrix(
    title: "Queue options",
    options: [
      {"id": "db", "label": "SQLite", "note": "One writer is enough."},
      {"id": "mq", "label": "Broker"},
    ],
    criteria: [
      {"id": "ops", "label": "Easy to run", "weight": 3},
      {"id": "scale", "label": "Scales out", "weight": 1},
    ],
    cells: [["yes", "no"], ["no", "yes"]],
    recommended: "db",
  )

stats - A strip of 2 to 6 headline numbers with an optional change

Fields:
  item   list of {label, value, delta, direction, good, tone, note, decimals},
         2 to 6; value is text or a number (numbers get thousands separators;
         decimals sets the places); delta is text or a number, shown as

  stats = stats(

      {"label": "Requests", "value": 1204331, "delta": "12%", "good": "up",
       "direction": "up"},
      {"label": "p95 latency", "value": "212 ms", "delta": "-8%", "good": "down"},
      {"label": "Error rate", "value": 0.4, "decimals": 2, "delta": "0.1 pt",
       "direction": "up", "good": "down"},
    ],
  )

sequence - A sequence diagram of actors and ordered steps, drawn as SVG

Fields:
  actors: list of {id, label}, 1 to 12
    id     unique actor name; label is the text over its lifeline
  steps: list of {from, to, text, kind, group}, 1 to 200, in order
    from, to  actor ids; the same id draws a self-call loop
    text      the message
    kind      optional: call (default, solid), return (dashed),
              async (open head) or note (a box across from..to)
    group     optional label; neighbouring steps with the same label sit
              in one labelled frame (alt, loop, opt style)
  desc        what the diagram shows, for screen readers
  title       optional text
    The steps are always also listed as text: 'A to B: text'.

Line syntax (in a ```ui fence):
  sequence = sequence(
    title: "Sign in",
    desc: "The browser signs a user in through the API and the user store.",
    actors: [
      {"id": "b", "label": "Browser"},
      {"id": "api", "label": "API"},
      {"id": "db", "label": "Users"},
    ],
    steps: [
      {"from": "b", "to": "api", "text": "POST /login"},
      {"from": "api", "to": "db", "text": "find user", "group": "cache miss"},
      {"from": "db", "to": "api", "text": "row", "kind": "return", "group": "cache miss"},
      {"from": "api", "to": "api", "text": "check password"},
      {"from": "api", "to": "b", "text": "session cookie", "kind": "return"},

  )

state - A state machine: states and labelled transitions, drawn as SVG

Fields:
  states: list of {id, label, kind, note}, 1 to 40
    id     unique state name; label is the text in its box
    kind   optional: initial (exactly one; gets a start dot), normal
           (default), final (double border) or error (cross mark)
    note   optional text shown in the text list
  transitions: optional list of {from, to, label, guard}
    from, to  state ids; the same id draws a self-loop
    label     optional event or action; guard is shown as [guard]
  desc        what the machine models, for screen readers
  title       optional text
    A state no path from the initial state reaches is marked unreachable.
    Transitions are always also listed as text: 'A to B on label [guard]'.

Line syntax (in a ```ui fence):
  state = state(
    title: "Job",
    desc: "A job waits, runs, and ends done or failed; failed jobs retry.",
    states: [
      {"id": "idle", "label": "Idle", "kind": "initial"},
      {"id": "run", "label": "Running"},
      {"id": "done", "label": "Done", "kind": "final"},
      {"id": "bad", "label": "Failed", "kind": "error"},

screen-flow - A flow of wireframe screens in lanes, joined by labelled arrows

Fields:
  screens: list of {id, title, grid, regions, surface, kinds, notes}, 1 to 12
    id, title  unique screen name and its caption
    grid, regions, surface, kinds, notes  as in wireframe (drawn at half size)
  steps: optional list of {from, to, label}, up to 20
    from, to  screen ids; a step joins neighbouring ranks of one lane
    label     optional text on the arrow

  title, desc  optional text; desc is a one-sentence summary

Recipes - assemble a recap or plan page from these components

Page order for a recap (omit any block with nothing to show; three blocks beat ten):
  1. One outcome sentence first, as plain prose. No intro, no summary prose.
  2. One block per kind of change:
       UI change      wireframe, before and after side by side in columns
       schema         data-model with change markers
       API            endpoint with change markers
       changed files  file-tree
       key changes    tabs holding diff and annotated-code blocks
       verification   checklist
       numbers        stats, only when real numbers exist
  3. Options and trade-offs: matrix with recommended.
  4. Risks: callout with tone risk; risks only when there are three or more.
  5. Open choices last, all in one form or choice set, each choice marking at
     most one option recommended: true. Settled choices: callout with tone decision.

Page order for a plan: outcome sentence, scope and non-goals (callout), approach
(diagram or sequence), file map (file-tree plus annotated-code), checklist of
acceptance criteria, risks, then the open-questions form.
