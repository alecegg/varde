## Ranked findings

Decision process completed; the chosen solutions and implementation outcomes are recorded below.

1. **Provenance recipe returns success after an input hash fails (correctness).** `skills/varde-docs/references/spec-format.md:46-48` invokes hashing inside `printf` substitution; a missing input produces an aggregate and exit 0. Reproduced with a nonexistent source path: stderr reports missing file, stdout is a plausible hash, status 0. This risks incorrect provenance and subsequent regeneration. Options: (A) separately assign each hash and explicitly abort, plus propagate pipeline failures; (B) use a small bundled Python helper that invokes git and fails atomically; (C) invoke an existing verified CLI aggregate operation if available. **Recommend A**, preserving the defined aggregate and avoiding another maintained helper. No actual spec was generated in this audit.

   **Chosen: A. Fixed 2026-09-28.** Compute and check each input hash separately, propagate pipeline failures, and publish the aggregate only after the complete computation succeeds. Verify unchanged aggregates for valid inputs and failure without a usable aggregate for missing inputs.

2. **Medium correctness: read-only evals accept committed forbidden changes.** `skills/varde-change/evals/verify-change-eval.sh:40` implements `path_is_clean` with `git status`, then calls it for byte-identical assertions at lines 191, 211, 239, 261, 270, 276, 288, 370 and 401. A scratch reproduction seeded eval 1, changed its plan from active to completed, committed that forbidden change, then ran its verifier. It returned PASS for “Leaves every plan, task, and handoff file byte-identical.” The existing `unchanged_since_seed` at line 75 already checks committed changes and untracked additions. This weakens the evidence the suite produces; replacing the weaker calls has low maintenance cost.
   1. **Recommended:** use `unchanged_since_seed` for every unchanged assertion with committed fixtures.
   2. Snapshot expected fixture bytes and compare hashes after execution.
   3. Assert HEAD equals seed as well as a clean working tree for strictly read-only cases.

   **Chosen: 1. Fixed 2026-09-28.** Reuse `unchanged_since_seed` for unchanged assertions with committed fixtures. Add a regression case proving a forbidden committed edit fails verification while unchanged fixtures pass.

3. **Correctness: missing Knowledge eval output aborts instead of emitting FAIL.** `skills/varde-knowledge/evals/verify-knowledge-eval.sh:8` runs `find … | head -1` inside an assignment under `set -euo pipefail`. Reproduced in a fresh temporary directory: `EVAL_ID=1 bash …/verify-knowledge-eval.sh` exits 1 with no output when the decision folder is absent. The intended FAIL assertions at lines 9-30 never execute. Larger folders may also produce SIGPIPE from `head`; this effect was not tested. This damages mechanically graded negative cases and adds diagnosis/retry work.
   - Options: (A) explicitly treat absent directory as an empty match and use a non-short-circuiting selection; (B) replace discovery with a small Python verifier that emits the same JSON; (C) remove the mechanical verifier for case 1 and let the judge grade it.
   - **Recommend A**, preserving cheap deterministic checks. Also avoid selecting an arbitrary pre-existing note: identify the requested output or compare pre/post files.

   **Chosen: 1 (A). Fixed 2026-09-28.** Guard missing output directories and replace the fragile `find | head` discovery pipeline while preserving structured verifier results. Verify missing output emits FAIL results and valid output retains expected results. Output identity improvements remain unselected.

4. **Medium correctness: named code-area reviews lack a route that includes unchanged files.** `skills/varde-review/SKILL.md:22` advertises reviewing a code area, but `references/report.md:16-27` derives changed files even when a user names an area, then narrows that changed-file list and stops when nothing remains. For a clean repository at its nearest release tag, “review src/api” produces an empty diff and can end without reading that area's code. Whole-codebase review is merely offered, although reviewing the named area is already authorized. The scope distinction needs one branch, not another workflow.
   1. **Recommended:** distinguish a requested diff/ref from a requested code area; enumerate tracked files under an explicitly named area and inspect its consumers.
   2. Add a dedicated “area review” entry route using the existing report phases.
   3. Ask whether a named area means full-area or changed-files only when the wording is ambiguous.

   **Chosen: 1. Fixed 2026-09-28.** Distinguish explicit area requests from diff/ref requests. Review all tracked files in the named area and relevant consumers for area requests; preserve changed-file scope for diff requests. Verify an area review still inspects code when the repository has no changes.

5. **Correctness: legacy handoff links can be labeled unchanged after local tracked edits.** `skills/varde-knowledge/references/reflect-handoff.md:95` falls back to `git log <head_sha>..HEAD -- <target>` for tracked legacy targets. That query sees commits only, so staged or unstaged edits with no new commit are invisible. The three labels then give an unjustified unchanged result. Legacy support has value but its current evidence is incomplete; inferred from documented command semantics, not end-to-end tested.
   - Options: (A) add staged/working-tree diff checks against the recorded commit; (B) label snapshot-less links unknown and require re-reading relevant targets; (C) explicitly migrate a legacy handoff to hashes on first resume while marking its previous state unverifiable.
   - **Recommend A**, using one combined diff against the recorded SHA and reporting unknown when SHA is unavailable.

   **Chosen: 1 (A). Fixed 2026-09-28.** Compare tracked targets against the recorded commit, including staged and unstaged edits; report unknown when the baseline is unavailable. Working memory is recommended outside the repository: resolve each linked target independently of the handoff's location. Preserve hash-based comparison for external targets; legacy external targets without a reliable baseline must not be called unchanged based solely on timestamps. Verify an external handoff linking both repository files and external memory files.

6. **Artifact storage and gate scope contracts disagree (correctness, runtime effect uncertain).** `skills/varde-prototype/SKILL.md:30-32,44-50` allows output in an externally configured working directory. `skills/varde-prototype/references/review-gates.md:37-38` requires repository-relative scopes and `:92-96` blocks prototypes without the gate.    **Chosen: 1 (A). Fixed 2026-09-28.** Support and document explicit external artifact scopes in review contracts, preserving independent approval, baseline/change evidence, and completion checks. Keep externally configured working memory supported without staging artifacts in the repository.    **Chosen: 1 (A). Fixed 2026-09-28.** Narrow mechanically emitted assertions to the observations actually verified, updating matching eval assertion strings.
