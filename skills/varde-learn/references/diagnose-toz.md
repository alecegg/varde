# Investigate Toz output friction

1. If `varde-toz` is installed, load `varde-toz`: use your skill tool, or read
   `../../varde-toz/SKILL.md`, and retrieve relevant existing captures in
   bounded pages with redacted searchable output. Without `varde-toz`, report
   the unavailable Toz evidence and continue from native session witnesses.
   This does not authorize raw retention, broader searches, or privacy changes.
2. Link each handle to a session anchor with command/source plus identity or
   timing evidence; matching command text alone does not prove the same
   execution. Record unlinked, missing, expired, redacted, or partial captures
   as coverage gaps.
3. For current or unknown overlap, use only verified links, limits, and frozen
   excerpts from before the cutoff. Keep proposed filters out of the evidence
   assessment. Cite handles and retrieval coverage in the report.
4. Compare preview size and retrieval effort on equivalent evidence, checking
   that failures and needed context survive. Report measured bytes, queries,
   or tokens separately; never infer savings from shorter output.
5. Put proposed Toz improvements in bounded recommendations. Use the removal
   option, audit lens, and outcome tag in [`options.md`](options.md). Load
   `varde-customize`: use your skill tool, or read
   `../../varde-customize/SKILL.md`, and route an authorized profile change to
   it with the command/source, current profile, representative bounded output,
   details to preserve, and measured baseline or unknowns; load
   `varde-change`: use your skill tool, or read `../../varde-change/SKILL.md`,
   and route core changes to it. If either is not installed, report the
   recommendation instead.

Captures supplement native session witnesses, which still govern capture.
