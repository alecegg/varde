Query: keyword-driven context bundle — files/symbols matching `query` plus their one-hop graph neighborhood, ranked and with covering tests. `rankingMode` accepts `fallback` (default; lexical retrieval runs only when structural matching finds fewer than 3 seed files) or `structural`. (see `context_pack` help for inputs)

Usage: varde map context_pack [OPTIONS] --json <JSON>

Options:
      --json <JSON>  JSON object: { repoRoot, dbPath?, query, resultsLimit?, resultsOffset?, maxTokensEstimate? (default 4000), includeOccurrences? (default false), fullResults? } maxTokensEstimate estimates the complete success envelope as serialized JSON bytes / 4, including metadata. Symbols default to declaration kinds; includeOccurrences=true adds matching occurrence/control entities. Each symbol span contains persisted 1-based start_line and end_line values. resultsLimit bounds each of files, symbols and tests. When the envelope exceeds maxTokensEstimate the lowest-ranked symbols and tests (then files) are dropped, and meta.truncated and meta.pagination.<section> report shown and total. resultsOffset pages files; symbols, tests and readingOrder follow the files shown, and symbols/tests totals count only those files (next_offset on files reaches the rest; symbols/tests have none). A budget always keeps at least one file, so next_offset advances. fullResults bypasses token and result caps without changing symbol filtering; resultsOffset still applies. Example: {"repoRoot":".","query":"authentication","includeOccurrences":true,"resultsOffset":0,"fullResults":false,"maxTokensEstimate":4000}. maxTokensEstimate estimates serialized success-envelope JSON bytes divided by four; it is not a tokenizer count
  -v, --verbose      Enable verbose logging (only applies when RUST_LOG is unset)
  -h, --help         Print help
